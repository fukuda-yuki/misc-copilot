# 学習の道筋

この文書は、BookCatalog の移行を学ぶときの**段階の一覧**です。
各段階の詳しい手順や実装コードは書いていません。目的と参照先をたどり、自分で調べて進めてください。

| 段階 | 目的 | 参照先 | 完了の目安 |
| --- | --- | --- | --- |
| 0. 環境を確認する | 自分の環境で使えるツールを知る | 確認コマンド（`git --version`、`dotnet --list-sdks`） | 使える .NET SDK とそのバージョンを、自分の環境で実際に確認できた |
| 1. 旧版を読む | 移行前の作りを知る | `shared-legacy-app/`、[BASELINE.md](BASELINE.md) | 画面・データ・起動時の処理の流れを説明できる |
| 2. 調査する | 何が変わるのかを洗い出す | 旧版ソース、[README の参考資料](../README.md) | 依存関係・古いAPI・DBの初期化方法を一覧にできた |
| 3. 計画する | 進め方を決める | [ACCEPTANCE.md](ACCEPTANCE.md) | 変更の順序、DBの保存場所、スキーマ管理の方式、確認の方法を決めて記録した |
| 4. .NET 10 へ移行する | 新しい .NET でビルドと起動を通す | [ACCEPTANCE.md](ACCEPTANCE.md) の A・B | 対象フレームワーク、ビルド、HTTPでの応答を確認できた |
| 5. SQLite へ移行する | 保存先をローカルのSQLiteファイルに変える | [ACCEPTANCE.md](ACCEPTANCE.md) の C | 実ファイルのSQLiteに保存し、プロセスを再起動しても残ることを確認できた |
| 6. 受入確認する | 「完成」を確かめる | [ACCEPTANCE.md](ACCEPTANCE.md) の D | 26条件の確認結果を、成功・失敗・未実施の区別をつけて記録した |

## 進め方の原則

- 各段階の終わりに、やったこと・確認したこと・**未実施**のことを短く記録します。置き場は任意です（自分のブランチに残します）。
- 確認していないことを「確認済み」と書かないでください。**未実施を成功扱いにしない**ことが、このサンドボックスの前提です。
- 受入条件（[ACCEPTANCE.md](ACCEPTANCE.md)）は、実装に合わせて黙って弱めません。矛盾を見つけたら、根拠を示してその部分だけを解決します。
